# 研发 UI 还原自查

在研发代码项目和运行环境中工作。用户提供 Figma 链接及网址、设备或已有截图时，优先读取真实页面；工具说明见 [README](../../../README.md)，配置和快照见 [接入规范](../../../docs/接入与快照规范.md)。创建文件前读取工具仓库根目录《问题与报错日志.md》。

## 首轮准备

- 确认用户本轮范围：开发中可只检查一个模块；完成后覆盖约定的页面、状态和设备。把范围写入配置，未完成模块不报缺失。
- Web/H5 使用可访问的网址与固定视口，复用用户提供的登录 storage state；App 使用已有 Appium 会话与当前页面。缺少原生驱动时用项目现有测试框架导出统一快照，不承诺所有平台共用同一个驱动。
- 读取 Figma 画板、Comment、Annotation、Measurement，逐类保留状态、原文、节点和范围。把适用的单位、动态内容、例外范围和容差转成配置；有冲突时仅暂停受影响部分。REST 未获取的测量说明可用现有 Figma 工具/界面补充。截图图像和结构属性都要使用。
- 设计单位到 logical_px 的换算由项目规则确定。浏览器报告 CSS px；原生树坐标与截图像素分别处理。不要固定 720，也不要按机型猜倍率。
- 首次由助手准备配置，保存到研发项目的本地配置目录。不要要求研发为每个元素手写映射。工具的 Node/Python 依赖在工具仓库安装。

## 检查与配对

运行 tools 仓库中的 scripts/yanfa_review.py check --config <绝对配置路径>。配置相对路径按配置目录解析，输出默认在工具仓库 outputs/。安装、Web、原生和离线入口按接入规范选择。

先读取 suggested-mappings.json、完整截图及局部证据，对自动配对做语义确认。名称、文字或几何相似不单独证明是同一元素；重复实例逐项核对。可靠匹配写回本地 mappings 并设置 confirmed=true，未知保持候选。稳定 selector、data-ui-review、accessibility ID 可选，必要时才建议研发补充。

检查容器与子元素的尺寸、位置、四边、间距、文字、颜色、圆角、图片与状态。按 [文案分类](COPY-CLASSIFICATION.md) 处理内容差异。脚本只自动测量暴露的属性；阴影、图形、图片内容、遮挡和动态边界仍需用截图复核。没有 DOM/原生属性时只能记录有依据的可见边界估算，不猜字号或源码位置。

先判断父容器问题是否导致一组子元素偏移；在报告中说明共同原因的证据，保留每项原始测量，不按相似文字自动合并。按实际影响给研发修复顺序，不把所有视觉差异都叫 P0。

## 修复与交付

- 首选 HTML 报告；JSON 保存测量与稳定 ID，Excel 用于汇总交付。无需上传截图到 Figma、建验收页或获取 Figma 写权限；在线表格和外部写入仅按用户本轮要求处理。
- 每项包含设计值、实际值、单位、差值、确认程度、来源节点和局部证据。源码文件/组件/样式位置必须在研发仓库中核实；未知时给排查方向。
- 自动结果和助手复核结果区分。助手补充的问题必须带检查依据与证据；不要为了凑完整覆盖虚构脚本测量。
- 当前命令只检查。用户要求修复代码时，在研发仓库按问题处理并检查受影响组件；只有“检查”请求时不直接改产品代码。
- 修复后以 --previous <上一轮/review.json> 重跑；--only 可限定设计节点。本轮可靠检查且基线一致才记复验已消除，范围外、缺属性、设计版本变化都记未复验。
- 保留人工 note/workflow_status，刷新实际测量。HTML/Excel 是本轮快照；不要声称人工改表会自动同步回 JSON。
- 完成时报告已确认问题、待确认候选、实际覆盖范围、未测项和复验结果。覆盖统计是配置属性覆盖，不是通用还原度分数；浏览器移动视口不能替代各原生平台真机验证。
