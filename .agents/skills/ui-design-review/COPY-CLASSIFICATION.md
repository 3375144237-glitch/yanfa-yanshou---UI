# 研发文案检查

文案性质决定是否逐字比内容，不影响样式、边界和布局检查。

| 类别 | 处理 |
|---|---|
| 固定 F | 按确定的设计内容逐字比较，包含标点、空格和全半角；配置 copy=fixed |
| 动态 D | 不比较示例值，仍检查样式、空值、换行、截断、边界和碰撞 |
| 模板 T | 固定前后缀与格式需要比较；变量长度和显示检查按动态内容处理 |
| 待确认 U | 内容不判定，保留样式检查；只询问影响结论的歧义 |

依据优先级：用户或项目已确认的字段规则 > Figma 评论/注释/测量标注 > 图层明确命名 > 可确认的组件属性与业务结构。课程名、价格、人数等常为动态；按钮文案常为固定，但都允许项目依据覆盖。不能因为两侧文案不同就把它归动态。

未知内容不要默认固定。首次分析记录依据，后续复用。设计版本或字段规则变化后重新核对。无需为了无关动态字段反复打断研发。

当前脚本自动支持固定文案逐字比较；模板匹配、长文本边界、图片内文字由助手结合设计说明、运行截图和源码复核，不能声明脚本已经全量检查。

研发报告可以展示明确的预期与实际内容，方便修改；应避免复制与当前问题无关的真实用户数据。对转曲/图片文字只记录有证据的视觉差异，不猜字体参数。
