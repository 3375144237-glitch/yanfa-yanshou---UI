# 接入与快照规范

## 配置

每个 JSON 配置对应一个可重复的页面状态：

- id：稳定页面用例名；state：默认态、弹窗等业务状态。
- design：url 指向 Figma 画板，units_per_design_unit 为每个 Figma 单位对应的 logical_px；或者 snapshot 指向本地设计快照、image 指向设计图。
- actual.type：web / native / snapshot。
- mappings：以设计节点 ID 为键，填写 selector（Web）、accessibility_id/resource_id（原生）或 actual_id（快照）；确认后加 confirmed=true。
- properties：可选，限制该映射检查的属性；copy=fixed 才逐字比较文字。source 是经源码核实的修复位置提示。
- scope：可选的设计节点 ID 数组，只检查这些节点。命令 --only 可覆盖它。
- tolerances：position/size/style，默认 1/1/0.5 logical_px（font_weight 等无量纲属性数值使用 style 容差），需按项目精度调整。

properties 支持 x、y、width、height、font_family、font_size、font_weight、line_height、letter_spacing、color、background_color、border_radius、border_width、padding_top/right/bottom/left、gap、text。presence 会自动加入。只有已确认映射且采集器明确查到节点不存在（mapping_queries 对应 ID 为 absent），才报告缺失；视口外、未暴露节点和原生树中找不到的元素保留待确认。复杂渐变、混合文字样式、不均匀边框等不从单值推断。font_family 比较声明字体，不等于已经验证每个字形实际使用的字体。

## Web/H5

actual.url 是运行网址；viewport.width/height 是 CSS px，dpr 是截图倍率（不改变 CSS 布局值）。ready_selector 是状态就绪标记，应指向该业务状态特有元素，避免把登录页或加载页当目标页。

可用字段：locale、timezone、color_scheme、storage_state、full_page、headless、channel。channel 可指定已安装的 chrome；默认使用 Playwright Chromium。storage_state 是本地登录状态文件，忽略提交。

actions 是显式配置的准备动作，支持 click(selector)、fill(selector,value)、press(selector,key)、scroll(selector)。这些动作会真实操作测试页面，配置时使用测试数据并明确目标状态；采集器不会自行探索或提交表单。

采集等待字体和图片，禁用 CSS 动画/过渡，截图前后比较结构和属性以识别状态变化。JS 动画、随机数据、倒计时仍需在测试场景中固定。错误码 PAGE_NOT_READY 通常是就绪元素缺失或采集中页面变化；PLAYWRIGHT_MISSING/BROWSER_MISSING 按 README 安装。

当前遍历主文档普通 DOM；iframe、Shadow DOM、Canvas 内部需要额外适配或视觉复核。元素部分超出截图范围记未覆盖。full_page 只拓展采集范围，不自动证明懒加载列表、sticky 状态正确。

## 原生 App

### 开发前的三端约束

同一业务页面先确定目标平台、各自画板和设备规格；只有通用画板时，结合研发仓库现有平台规范确定差异，不把一张图机械缩放到三端。实现前逐端核对：设计是否包含状态栏/导航栏/手势区域，安全区由系统容器还是页面负责；系统字体、字号缩放、图片密度和资源命名；键盘弹起、长文案、深色模式及加载/空/错误状态。共用业务组件可以复用，系统导航和安全区等差异在对应平台实现。运行截图与设计使用相同的内容原点，避免重复加或漏加系统区域。

- iOS：按项目实际 UIKit/SwiftUI 约束处理 safe area、point、动态字体和导航容器，不假定截图像素等于 point。
- Android：按项目实际 View/Compose 约束处理 WindowInsets、dp/sp、屏幕密度和 fontScale；确认是否启用边到边布局，不把状态栏高度写死。
- 鸿蒙：按项目实际 ArkUI 或跨端框架核对安全区、系统栏、布局/字体单位（如 vp/fp）及资源目录；先确认运行环境或测试框架能提供什么可观测数据，不套用 Android 的坐标与驱动假设。

各端设计与运行结果分别建立用例、设备环境和复验基线。同一个视觉差异可以关联为共同根因，但一端通过不能证明另两端通过。未提供某端设计或运行环境时，记录该端依据/验证缺口，不写成三端已还原。

### 运行采集

actual.server 指向运行中的 Appium（默认 http://127.0.0.1:4723）；session_id 来自已有会话。工具只 GET source 与 screenshot，不创建/关闭会话，不启动或重置 App。

先导航到目标页面。viewport 是截图完整范围对应的逻辑宽高；tree_units_to_logical 是 XML 坐标到 logical_px 的倍率。例：iOS XML 已是 point 时常为 1；Android 驱动可能返回物理像素，需要项目确认后换算，不能一律除 2。tree_origin 可声明树坐标原点偏移，默认 x=0,y=0。截图纵横比必须与声明视口一致。

platform、device、runtime 用于复验环境识别，填写实际平台、机型/模拟器、系统与驱动版本。不同环境不能互相消除问题。原生 XML 支持 Android bounds 和 iOS x/y/width/height，保留未暴露样式为空。鸿蒙和自研容器需对应驱动或快照导出，不能直接声称 Appium 通用支持。

鸿蒙没有兼容现有采集接口且已验证的驱动时，使用 `actual.type=snapshot`：项目测试框架导出截图及同一状态的元素快照，按下节 schema 转成 logical_px，并写入 `platform: "harmony"`、`environment.device`、`environment.runtime`。配置中的 `actual.snapshot` 和 `actual.image` 指向这两份文件；路径相对配置文件目录。只填可由真实运行环境证明的 bbox、文字和样式，缺失属性保持未知。当前工具没有内置鸿蒙页面导航、元素树解析或截图采集能力。

## 统一快照（供 MCP / 现有测试框架导出）

```json
{
  "schema_version": 1,
  "coordinate_unit": "logical_px",
  "version": "design-version",
  "viewport": {"width": 360, "height": 640},
  "elements": [
    {
      "id": "1:23",
      "name": "课程卡片",
      "bbox": {"x": 16, "y": 100, "width": 328, "height": 180},
      "style": {"padding_left": 16, "border_radius": 12},
      "figma_url": "https://www.figma.com/design/FILE?node-id=1-23"
    }
  ],
  "instructions": {
    "comments": {"status": "empty"},
    "annotations": {"status": "empty"},
    "measurements": {"status": "empty"}
  }
}
```

示例 empty 表示采集方已经检查且确实为空，不是默认填充值。read 应保留 items；unavailable 附 reason；waived 必须有经确认的本轮 reason。读取成功不代表说明已执行，助手仍需把说明映射到检查配置。

设计 snapshot.version 可用 Figma 版本/导出标识。工具还对实际元素与依据内容哈希，防止同名版本被替换后误关问题。实际快照还需 platform 和 environment（设备、浏览器、系统、DPR 等）；所有 bbox 都是当前截图原点下的逻辑边界。id 非空且唯一，坐标有限、尺寸为正；重复组件各有独立 ID。

颜色使用 #rrggbbaa。style 只填能证实的值；未知字段省略，不能填猜测或 0。visible=false 的设计子树不加入应验清单。图片可单独提供给 design.image / actual.image，路径相对配置目录；工具按该侧逻辑视口等比归一，拒绝纵横比冲突，不为追求重合而拉伸。

## Figma 说明与稳定基线

REST 自动读取节点、PNG、普通评论和节点 Annotation。Measurement 在当前采集器中为 unavailable；助手可另行读取后用 design.instructions 引用 JSON（只含 comments/annotations/measurements 对象）补充状态和记录。

推荐首次获取设计后保存输出的 design.snapshot.json 与 design.png，后续配置指向这份已核对的快照。这样每轮复验基于同一设计版本；设计更新时主动建立新基线。

## 结果与处理状态

review.json 是本轮事实；findings.status 为 confirmed/candidate，workflow_status 和 note 为人工字段。默认保存 JSON 和可用的截图证据；加 `--xlsx` 才导出 Excel，编辑表格不会写回 JSON。下一轮从 --previous 指向的 JSON 继承人工字段，但不继承过期的描述、测量或设计值。

retest 的 resolved 只表示旧问题本轮在相同条件下已通过；still_present 表示仍存在；not_rechecked 表示条件变化或依据不足。范围缩小时，未覆盖旧问题仍保留未复验；issue_history 跨轮保留这些记录，即使连续多轮无法测量也不会丢失。更换元素绑定会暂停旧问题自动关闭。不同设备分别跑配置，分别保存结果；相同根因可由助手建立关联，但不抹掉设备实例。
